# Moos DSH 风格前端、插件与长任务运行时设计

日期：2026-11-05
状态：用户已确认设计，尚未实施
适用范围：正式 Mac 桌面产品；iPhone 复用版本化数据协议但单独实现移动布局

## 1. 目标与边界

Moos 采用“选择性移植 DeepSeek Harness 原版前端 + Moos 适配层”的方案：复用其布局、样式和交互优点，继续使用 Moos 自己的 Tauri 2、项目与会话数据、任务调度、PI、SQLite、模型配置、电脑操作和手机连接。

本设计不引入 DeepSeek Harness 的 Electron 桌面壳、Cordis 后端、Profile 执行内核、模型和工具后端、Node Web Server、官方名称、Logo 或其他容易造成官方背书误解的品牌素材。DeepSeek Harness 源码为 MIT；任何实际移植的源码或实质性片段必须保留其版权和许可声明，并在第三方声明中标出来源。设计核对基线固定为 `deepseek-ai/deepseek-harness@fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，不得无审查跟随上游开发预览版本。

本设计确认的首批范围包括：

- DSH 风格的三栏页面、工作区/会话导航、对话与轨迹、固定输入区和完整设置中心。
- 输入区三档权限、模型选择、缓存命中率、上下文用量和后台任务状态。
- 本地 Token/缓存/费用统计。
- 内置插件与本地 ZIP/文件夹插件，包含皮肤和低权限前端功能插件。
- 单一隐藏运行时（Moos Agent Runtime）、PI SDK 会话、可配置长任务上限和可解释错误。
- 后续内置终端、Git 管理、电脑操作和手机控制所需的页面与能力边界。

首版不包括在线插件市场、第三方原生插件、第三方任意 Shell/文件系统/电脑控制权限、Windows/Android 完整适配或跨设备云同步。

## 2. 总体架构

```text
DSH 风格 React 页面
        ↓
Moos UI Adapter
        ↓
Tauri Command / Event
        ↓
Moos Agent Runtime
        ↓
PI SDK + SQLite + 本地工具
```

前端只消费 Moos 的版本化视图模型，不读取 SQLite、密钥文件或 PI 内部文件。适配层把 `projects`、`conversations`、`messages`、`tasks`、`events`、`providers` 和 `usage` 投影为页面所需的数据，并把页面动作转换为类型化命令。DSH 组件中依赖 Cordis、DSH RPC、Slots Store 或 Profile 的部分不得直接连接 Moos；应拆出可复用的展示组件，或以等价交互重新实现。

正式产品从 RPC 子进程迁移到 PI 1.5.0 的进程内 SDK 会话。该决定只适用于正式产品后续实现；M01 探针和已有 RPC 验证证据保持历史原样。迁移前必须以独立可回滚任务验证 SDK 的会话恢复、并发、取消、工具事件、模型代理、退出清理和包体影响。

## 3. 页面信息架构

桌面采用三栏结构：

```text
┌────────────左侧栏────────────┬──────────对话主区──────────┬────右侧面板────┐
│ Moos / 新建会话              │ 会话标题 / 对话 / 轨迹     │ 文件预览       │
│ 工作区搜索                   │ 消息与工具执行时间线       │ Git            │
│ 项目                         │ 固定底部输入框             │ 终端           │
│ └─ 会话                      │ 权限 / 模型 / 发送 / 停止  │ 任务详情       │
│ 自动化任务 / 插件 / 设置     │ 缓存命中 / 上下文 / 后台数 │ 插件面板       │
└──────────────────────────────┴────────────────────────────┴────────────────┘
```

右栏按需打开，没有内容时收起。主区提供：

- **对话视图**：用户消息、助手公开输出、公开状态、工具卡片和执行结果。
- **轨迹视图**：按时间查看模型请求、工具动作、模型切换、重试、停止和失败原因。

Think 或等价组件只展示模型公开返回、工具动作、可解释状态与切换原因，不生成或补写不可见思维链。

输入区包含附件/引用、权限选择、模型选择、自动路由原因、发送/停止、当前项目/分支。输入框下方固定展示：

- 缓存命中率：仅使用服务商返回的缓存 Token，缺失时显示“暂无数据”。
- 上下文用量：`当前上下文 Token / 模型上下文上限`，70%/85%/95% 分级提示。
- 当前会话之外的后台任务数。

Mac 桌面先完整实现；iPhone 复用同一数据协议和信息结构，但以 uni-app x 重新实现移动布局，不复制桌面 DOM。

## 4. 权限模式

新会话默认使用“帮我批准”：

1. **请求批准**：编辑外部文件或使用互联网等敏感操作前询问。
2. **帮我批准**：普通项目内开发直接执行，仅对检测到的高风险操作询问。
3. **完全访问权限**：在已授权能力范围内直接执行。

“完全访问权限”不得绕过 macOS 屏幕录制、辅助功能、相机和本地网络等系统授权，不得绕过项目归属、规范化目录锁、任务停止和插件权限边界。

## 5. 设置中心

设置中心包含：

1. 常规：语言、启动、更新、外观与行为。
2. 模型服务：GLM Coding Plan、OpenAI 中转站、模型能力和连接测试。
3. 模型路由：成本优先、自动升级、手动指定、任务费用和时长上限。
4. 权限：默认档位、项目权限和电脑操作权限。
5. 用量统计：Token、缓存、费用、模型、项目、会话和时间区间。
6. 插件：安装、启停、更新、卸载、权限和兼容性。
7. 皮肤：预览、应用、恢复默认和导入。
8. 数据与隐私：本地密钥文件、日志、截图、历史和清理。
9. 手机连接：同 Wi-Fi 配对、设备、撤销凭据和连接状态。
10. 高级：并发、上下文策略、任务上限和诊断。

## 6. 插件与皮肤

首版支持内置插件和本地 ZIP/文件夹安装，不提供在线市场。功能插件与皮肤分别声明 `type: "ui"` 和 `type: "theme"`；后续本地集成插件使用 `type: "integration"`，MVP 不向第三方开放。

功能插件包根目录必须提供 `plugin.json` 清单，至少包含：`id`、`name`、`version`、`type`、`moosVersion`、`entry`、`slots` 和 `permissions`。皮肤清单至少包含 `tokens`、`styles` 和 `assets`。安装时检查清单、兼容版本、入口、文件数量、总体积、权限、路径穿越、符号链接和禁止的原生可执行文件。

首批固定 Slot：

- `sidebar.primary`
- `sidebar.footer`
- `conversation.header`
- `conversation.message`
- `conversation.tool`
- `composer.leading`
- `composer.trailing`
- `rightPanel.tab`
- `settings.section`
- `usage.metric`

UI 插件在隔离环境中运行，只能经版本化 Moos Plugin API 注册 Slot、读取脱敏项目/会话信息、读取主题变量、保存自己的配置、发送通知和切换自己的面板。MVP 不开放模型密钥、任意文件系统、任意 Shell、鼠标键盘、截图、未声明网络访问或其他插件私有数据。

皮肤仅能提供主题变量、指定区域 CSS、字体、图标和静态背景素材，不能替换业务状态、执行任务或读取密钥。先在隔离预览区试穿，显式应用后才保存；加载失败自动回退；不兼容皮肤自动禁用并说明原因。

插件生命周期为“发现 → 校验 → 安装 → 启用 → 沙箱加载 → 注册 Slot → 停用并撤销 → 卸载”。所有注册必须有可重复执行的撤销句柄。插件崩溃、超时、内存超限或连续错误后自动停用，不能拖垮主页面。卸载时允许保留配置或清除插件自己的数据。

## 7. 单一运行时与长任务

生产环境页面直接加载 Tauri 打包的静态资源，不启动 Vite、DSH Web Server 或插件 Web Server。目标进程结构为：

```text
Moos.app
└── Moos Agent Runtime（隐藏、常驻一个）
    ├── 多项目调度
    ├── PI SDK 会话
    ├── 模型诊断
    ├── Token/缓存统计
    └── 插件权限桥接
```

提交对话不得再临时启动可见的 Node/PI 可执行文件。PI 仍依赖 Node 运行时，因此活动监视器中可存在一个稳定的、无窗口的 Moos Agent Runtime；不能宣称完全没有 Node 运行时。终端工具产生的 `zsh`/`bash` 子进程不属于额外 Node 服务，仍须按任务和项目归属清理。

任务默认上限为 2 小时，可选 10 分钟、30 分钟、1 小时、2 小时、6 小时和 24 小时；不允许无限执行。每个任务记录心跳、最后事件和阶段。模型仍在输出或工具仍在执行时不得误判断线。应用重启后未完成任务标记为“已中断”，不得静默成功或自动重放。

当前实现的已观察缺陷必须形成回归验收：两项实际任务分别在 600.0 秒和 600.1 秒失败，根因是 PI 适配器将任务上限硬编码为 600000ms，并由调度器把真实错误抹成 `Task execution failed`；当前每项任务还通过 `spawn(process.execPath, ...)` 启动 PI RPC 子进程。实施必须移除该固定上限和逐任务 Node 启动路径，并保留可配置有界超时。

错误至少区分：用户停止、任务上限、认证失败、额度不足、限流、模型/端点不支持、网络断开、PI 会话异常、工具失败、权限不足、运行时退出和应用关闭中断。未知错误使用可追踪错误码，不能只显示统一英文文本；日志仍须脱敏。

## 8. Token、缓存与费用

PI/模型返回的真实 usage 事件写入 SQLite：输入、输出、缓存读取、缓存写入、推理 Token（若有）、总量、服务商费用（若有）和带价格版本的本地估算费用。

缓存命中率定义为：

```text
cacheRead / (input + cacheRead)
```

分母为零或服务商未返回缓存字段时显示“暂无数据”，不得估算。设置页提供今日、近 7 天、近 30 天和累计视图，可按模型、服务商、项目和会话筛选，并支持导出和清理。密钥、原始模型请求和原始屏幕图像不得进入统计。

## 9. 内置终端与后续插件

当前 Moos 没有可交互终端，只有 PI 后台 Bash 工具和工具结果卡片。后续内置终端作为受信任的 integration 插件实现，使用 Tauri 原生 PTY，不增加 Node Web Server。终端支持项目工作目录、多标签、实时输出、停止和恢复；进程归属项目并与任务停止和目录锁协同。iPhone 首版只读终端输出，不开放任意命令输入。

Git 管理插件继续按 PLAN.md 的 D01 分阶段实现，并复用同一规范化目录锁、插件能力桥接和右侧面板 Slot。

## 10. 测试与实际验收

每个实施阶段必须增加单元、集成和界面测试，并完成对应实际验收后才能勾选：

- 页面：工作区/会话、对话/轨迹、设置、右栏、键盘和窄窗口布局。
- 适配层：快照映射、命令映射、增量事件、旧版本拒绝和断线恢复。
- 插件：清单、路径、权限、沙箱、Slot 生命周期、崩溃隔离、升级回滚和数据删除。
- 皮肤：预览、应用、回退、资源限额、不兼容禁用和默认主题恢复。
- 运行时：空闲/单任务/双项目进程树、超过 10 分钟的真实任务、各档超时、停止、崩溃和退出清理。
- 用量：真实 usage 入库、缓存缺失、跨模型统计、重启恢复、导出和清理。
- 安全：插件不能读取密钥、其他插件数据或未授权项目资源。

桌面 GUI 必须证明连续提交任务不会出现 Node 窗口或 Dock 闪烁。自动进程测试不能替代肉眼 GUI 验收；GUI 观察也不能替代进程树、退出清理和超时回归测试。

## 11. 分阶段交付

1. 固定第三方来源、建立 Moos UI Adapter 契约和静态页面骨架。
2. 移植布局、工作区/会话、对话/轨迹、输入区和设置中心。
3. 修复长任务错误，验证 PI SDK 单一运行时后替换逐任务 RPC 子进程。
4. 持久化 usage，完成缓存/上下文状态和设置用量页。
5. 实现 Slot、内置插件和皮肤预览/切换。
6. 实现本地插件包、沙箱、权限、生命周期和失败恢复。
7. 增加受信任内置终端；Git 插件继续依 D01 单独排期。
8. 完成打包、体积、GUI、进程、真实模型和安全验收。

任何阶段不得以按钮存在、模拟数据、单元测试或构建成功替代真实验收。在线插件市场在上述能力稳定后另行设计。
