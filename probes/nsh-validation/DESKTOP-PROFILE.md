# NSH 独立历史与接替门禁（N01-D2）

## 已验证：合成数据下的后端续聊

- 受信测试入口可把独立、已创建的 canonical 0700 空目录传给 `startDesktopHost({ profileDir })`。有数据后只接受本探针自己的版本标记；没有通过 UI／RPC／环境或命令行将任意路径接为用户资料的入口。既有 fixture/live 应用入口仍是临时状态。
- 保存项目、会话、SQLite 文本、工作区和 PI 会话。正常 EOF 撤销新任务，等待 Scheduler 退出、关闭数据库，再释放独占标记。未确认排空则保留数据和标记。并发启动、残留标记、缺数据或顶层目录/库被链接重定向都拒绝，不自动新建、删除或解锁。此机制针对独立可信目录，不是文件系统沙箱；同用户不得手动修改运行中的资料。异常终止后的解锁/恢复流程尚无实现。
- `desktop-profile.test.mjs` 用两个先后启动的 Node 子进程，经私有 stdin/stdout 和真实 PI SDK 连本机回环模型。第二进程保留项目枚举和会话 ID／标题／创建时间，工作区文件和旧 SQLite 消息不变；新请求带有上一轮两条合成消息。模拟遗留任务变为 `interrupted`，不自动重跑。旧任务流游标和提交幂等索引仍是当前 Host 的临时状态，重启后不恢复。此测试不等同于真实断电恢复、GUI 重新加载旧消息或外部服务验收。
- 本机构建运行一次临时（非持久）Catalyst 脚本回归：17 项通过、Host 正常退出。仅证明既有路径未失效；不是已打包的持久版，且仍依赖本机的开发运行时及未纳管的既有 UI 输入。证据：`desktop-profile-evidence.json`。

## 已验证：合成候选窗口重开与原会话续聊

使用 Node 24.15.0 和本机已有 Xcode/NSH 工具链：

```sh
node probes/nsh-validation/verify-desktop-pi.mjs --persistent
```

- 新标识 `dev.muma.probe.nsh.piui.persistent`；只用每次构建目录下固定的私有合成 profile。验收脚本两次**启动同一份** `.app`，不是把两次构建的数据混合。运行时指向本机 Node 和检出目录的 PI/Host 依赖；本机签名检查通过，不是独立可发行包。不和 `--live-models` 同用，不读取模型配置，不请求外部模型。
- 新增只读 `sessions.history({ projectId, sessionId, before })`，仅持久合成构建的 Swift 调用清单与私有 Host 放行。每页最新 12 条，以消息 ID 取更早一页，页内按旧到新排列；预览最多 4096 个码点，界面本次最多加载 120 条。只读本次 Host 启动前的用户/助手文本，不返回工具/系统消息或任务流、不重复本次实时行，不含导入、编辑和任意路径。换选丢弃旧页和过期返回；首屏历史失败可重试，加载失败不把历史冒充为空。旧数据未删除。
- 第一次脚本发送合成消息、等待完成且排空并清洁退出；第二次在任务事件数为 0 时读到两条历史，切换另一项目确认无串话，再返回同一会话并捕获窗口。新请求只有真实 PI 附带上一轮用户和助手文本时才得到通过标记。两次 Host 均正常退出、stderr 0 字节、无强制终止并释放独占标记。验收回执和截图摘要见 `desktop-persistent-evidence.json`，图和原报告留本机。
- 这是原生窗口内的脚本动作，非实键盘输入、人工 Quit 或强制退出恢复；未恢复最后一次选中的项目/会话，仅证明可切回同一历史会话。翻页的排序、限制和游标隔离由 Host 测试覆盖，不是人工长消息滚动签收。常规临时和外部模型模式仍不暴露此接口。

## 打包与迁移顺序

1. 上述独立数据和历史窗口已通过合成脚本验证。继续验证人工正常退出、异常退出后的安全恢复，确认打包输入归属；做能独立运行的签名候选包，不从源码路径取 Node/Host 脚本，不把密钥打入包。
2. 在合成资料上实现导出、校验和独立导入。正式版为 Electron/DSH/PI，不把某一个 SQLite 文件当成全部聊天：区分 DSH 历史与 PI 库及会话日志，并核对分支、附件、项目路径及只读归档和可继续聊两类能力。列明不支持的资料及原因；项目只保留原工作区链接，不复制代码。模型凭据不混入历史包，插件、皮肤和配置另列是否支持。
3. 说明正式数据的具体只读范围、备份方案及回退方法，经用户确认后才开始。保留原目录、原包和备份；导入到未使用的候选资料目录，不覆盖旧聊天或候选自建内容。不把历史送给模型来验证导入；用脱敏计数、标识、内容校验及用户选的会话核对。继续聊时，选定模型会收到本轮所需的会话上下文。
4. 两边验对且确认无运行中任务后，才办理切换并停用正式版。旧程序及资料保留为回退，不卸载、不删。回退使用原件；切换后候选新增记录独立存在，不自动反向合并。

当前未读取、备份或迁移任何正式资料，未安装正式替代包，未退出正式版。
